# VPNSTAN v24.1 — Fixes

## Railway startup crash
The generated Nginx configuration is created from a shell heredoc. Nginx variables such as `$http_upgrade`, `$host`, `$scheme`, and `$proxy_add_x_forwarded_for` must be escaped so the shell does not try to expand them.

The previous build failed with:

`/start-vpnstan.sh: line 26: http_upgrade: parameter not set`

This build escapes those variables correctly. `${PORT}` remains intentionally shell-expanded.

## Validation
- `sh -n scripts/start.sh`
- `python3 -m py_compile web/server.py`
- Generated Nginx heredoc expansion checked with `PORT=8080`
- No unescaped shell variables remain in the Nginx heredoc except `${PORT}`

Docker/Xray runtime itself was not executable in the local validation environment because Docker is unavailable there.
